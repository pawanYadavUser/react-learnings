More interview questions:-
1️⃣ Why is there only one HTML file in React?
Core answer:
React is a Single Page Application (SPA) framework. It uses one HTML file (public/index.html) and 
updates the UI dynamically using the Virtual DOM, without full-page reloads.
Extra detail for brownie points:
When the app loads, React injects components into the <div id="root"></div> in index.html. 
Navigation and state updates are handled client-side, improving performance.

2️⃣ What is the role of Webpack in create-react-app?
Core answer:
Webpack is a module bundler. It takes all your JavaScript, CSS, images, and other assets, and bundles them into
 optimized files for the browser.
Extra detail:
In development: Provides Hot Module Replacement (live reloading).
In production: Minifies and optimizes files for faster load times.
It uses loaders (like Babel loader) to handle JSX and ES6+ code.

3️⃣ What is the role of Babel in create-react-app?
Core answer:
Babel is a JavaScript compiler that converts modern JavaScript (ES6+, JSX) into browser-compatible JavaScript.
Extra detail:
Converts JSX into React.createElement() calls.
Ensures compatibility with older browsers by transpiling features like async/await, optional chaining, etc.

4️⃣ Why use npx instead of npm install -g for create-react-app?
Core answer:
npx runs the latest version directly from npm without installing globally, avoiding outdated CLI issues.
Extra detail:
This ensures every new project starts with the most up-to-date configuration and dependencies.

5️⃣ What happens when you run npm start in a CRA project?
Core answer:
It starts the development server (Webpack Dev Server) and serves the React app on 
http://localhost:3000 with hot reloading.
Extra detail:
Watches your source files for changes.
Recompiles and refreshes the browser automatically.
Uses in-memory bundling (not writing compiled files to disk).

6️⃣ What happens when you run npm run build?
Core answer:
It creates an optimized production build in the /build folder.
Extra detail:
Minifies JS/CSS files.
Generates hashed filenames for caching.
Optimizes images.
Prepares files for deployment to a static server or CDN.

7️⃣ What is the difference between public and src folders?
Core answer:
public: Static assets served as-is (not processed by Webpack).
src: Source code compiled and bundled by Webpack.
Extra detail:
If you put something in public, you must reference it with /filename or process.env.PUBLIC_URL.

what is virtual DOM?
The Virtual DOM is a lightweight in-memory representation of the actual DOM (the HTML structure rendered in the browser).
Think of it like a JavaScript copy of the real DOM that React uses to figure out what actually 
needs to change before touching the browser DOM.

Why Virtual DOM exists
The real DOM is slow: Every time you directly manipulate it (e.g., document.getElementById().innerHTML = ...), 
the browser has to reflow/repaint the UI, which is expensive.

React instead:
Keeps a virtual copy of the DOM in memory.
Updates that virtual copy when state or props change.
Compares the new virtual DOM to the previous one (diffing algorithm).
Applies only the minimal set of changes to the real DOM (reconciliation).

How it works (Step-by-step)
Initial Render
React creates a Virtual DOM from JSX and renders it into the actual DOM.
State/Prop Changes
React updates the Virtual DOM first.
Diffing
React compares the updated Virtual DOM with the old Virtual DOM.
Finds the differences (nodes that actually changed).
Reconciliation
React updates only those specific parts in the real DOM.
e.g.,
Without Virtual DOM:
document.getElementById("count").innerHTML = newCount;
→ Browser updates and re-renders everything in that part of the DOM.
With Virtual DOM:
React sees only count changed → updates just that node in the real DOM.

        React Component (JSX)
                 │
                 ▼
       Virtual DOM (in memory)
                 │
       State/Prop Changes
                 │
                 ▼
     New Virtual DOM (updated)
                 │
     Diffing Algorithm (compare old vs new)
                 │
         Changes Identified
                 │
                 ▼
     Real DOM (apply minimal updates)
                 │
         Browser re-render


1️⃣ What is the DOM?
DOM = Document Object Model
It’s not HTML itself — it’s a tree-like, in-memory representation of your webpage
 that browsers create so JavaScript can interact with it.
Think of it like:
📄 HTML file → 🌳 DOM tree in browser memory
When your browser loads HTML, it parses it and turns it into objects (nodes) in a tree
structure.

3️⃣ Key facts about the DOM
It’s live → If HTML changes (via JS), DOM updates instantly.
It’s an API → JavaScript uses it to read/change the page.
It’s hierarchical → Every tag is a node; nodes can have children.
It’s language-agnostic → Not just JS; any language that can access it can modify it.

4️⃣ Interacting with the DOM
You use the DOM API in JS to manipulate it.
Select elements:
document.getElementById("title");
document.querySelector("p");
document.querySelectorAll("h1");
Change content:
document.getElementById("title").textContent = "Hello Developer!";
Change style:
document.querySelector("p").style.color = "blue";
Add new elements:
let newItem = document.createElement("div");
newItem.textContent = "New section added!";
document.body.appendChild(newItem);

5️⃣ DOM vs HTML
HTML	DOM
Raw code in .html file	In-memory object structure
Static	Live & dynamic
Can’t directly interact	Can be read/modified via JS

6️⃣ Why Frontend Devs Must Understand It
Every click, input, or animation you code manipulates the DOM.
Frameworks like React, Angular, Vue ultimately update the DOM — they just do it more efficiently.
If you understand the DOM deeply, debugging UI issues becomes much easier.

5. useEffect Intro
useEffect is a function that takes two arguments 
one function :- called effect 
one empty array :- dependency array.
It is used to perform side effects in a component.e.g., 
- updating a DOM
- fetching details or timers


if dependency array is empty then the effect function only executes once for the first time render.
after that, effect function wont be executed for successive re-renders.
But if no dependency array is provided, then it will be executed after every render!
And components usually renders after each n every props or state update.

6. Component did mount and Update:-
if no dependency array is passed , then useEffect's effect function will be executed after every re-renders.
useEffect hook is used inside a JSX component, so it has access to all the states and props.

7. Conditionally run the effect:-
Pass the state in the dependency array, so that if it is updated, then useEffect effect function will be executed

9. Component will unmount:-
e.g., EffectComponentWillUnmount.js
useEffect(() => {
  // 1. Effect code runs only ONCE (after first render)
  
  return () => {
    // 2. Cleanup runs ONLY when the component UNMOUNTS
  };
}, []);

✔ First render
React renders your component
THEN it runs the useEffect() callback
The cleanup function is registered, but NOT executed
❌ Cleanup NOT executed here
✔ When does cleanup run?
Cleanup runs ONLY when:
The component unmounts
OR the effect is about to re-run (if dependencies change — but here they don't)
Since your dependency array is [], the effect NEVER re-runs, so cleanup ONLY runs on unmount.

🎯 So why doesn’t cleanup run immediately?
Because React follows this flow:
1️⃣ Render component
2️⃣ Run effect (mount phase)
3️⃣ Wait... component stays mounted
4️⃣ Cleanup only when component unmounts
React never runs cleanup right after the effect runs.

12. useReducer
useReducer
👉 Best for complex state logic
Useful when your state has multiple sub-values or when updates depend on previous state.
Similar to Redux reducer pattern.
Updates state based on actions.

When to use
When the state is complex or deeply nested.
When multiple actions update the same state.
When you want centralized state update logic.
When the next state depends heavily on the previous state.
When you want more predictable and testable updates.

| Feature        | useState                    | useReducer                        |
| -------------- | --------------------------- | --------------------------------- |
| Best for       | Simple state                | Complex state                     |
| Update style   | Direct setter               | Dispatch actions                  |
| Logic          | Inline inside component     | Centralized in reducer            |
| Ideal when     | Few actions, simple updates | Many actions, complex transitions |
| Learning curve | Easy                        | Medium                            |
