2. Hooks — VERY IMPORTANT

I would spend significant time here.

Know:

useState
const [count, setCount] = useState(0);

Understand:

state updates
re-rendering
functional updates
setCount(prev => prev + 1);
useEffect
useEffect(() => {
    fetchUsers();
}, []);

Know:

dependency array
mount/update behavior
cleanup
common mistakes
API calls

Especially:

useEffect(() => {
    ...
}, []);

vs

useEffect(() => {
    ...
});

vs

useEffect(() => {
    ...
}, [userId]);
useMemo
const result = useMemo(() => expensiveCalculation(data), [data]);
useCallback
const handleClick = useCallback(() => {
    ...
}, []);
useRef
const inputRef = useRef(null);

You should understand why useRef doesn't cause a re-render when its value changes.

3. React rendering — HIGH PRIORITY

This is where interviewers can distinguish someone who has actually used React.

Understand:

State changes
     ↓
Component re-renders
     ↓
React creates new virtual representation
     ↓
Reconciliation
     ↓
DOM updates where required

Know:

Virtual DOM
reconciliation
component re-render
key
parent re-render → child behavior
React.memo

Example:

const User = React.memo(({ name }) => {
    console.log("render");
    return <div>{name}</div>;
});

Know when React.memo helps and when it doesn't.

4. TypeScript — VERY IMPORTANT

Because the JD explicitly says TypeScript expertise.

You should know at least:

Basic types
let name: string;
let age: number;
let active: boolean;
Interfaces
interface User {
    id: number;
    name: string;
    email: string;
}
Type aliases
type User = {
    id: number;
    name: string;
};

Know:

interface vs type

Generics

Very important:

function identity<T>(value: T): T {
    return value;
}

And:

const users: Array<User> = [];
Union types
let id: number | string;
Optional properties
interface User {
    id: number;
    name?: string;
}
any vs unknown

You should be able to explain why excessive any is bad.

Priority 2

These are worth knowing but don't spend hours on them.

Jest

Know:

test("adds numbers", () => {
    expect(add(2, 3)).toBe(5);
});

Understand:

unit testing
mocking
describe
test
expect
mocking API calls
Cypress

Understand what it is:

End-to-end testing framework used to test application behavior in a real browser.

Example scenario:

Open login page
   ↓
Enter username/password
   ↓
Click Login
   ↓
Verify dashboard

Don't spend hours learning Cypress syntax.

Vite

Know the purpose:

Vite is a modern frontend build tool and development server commonly used with React.

Understand:

React source
   ↓
Vite
   ↓
Build/bundle
   ↓
Production assets

You don't need deep Vite internals.

Enzyme

Low priority.

Know what it is and that it was used for React component testing.

If they ask:

"Have you used Enzyme?"

Don't fake experience.

You can say:

"I understand Enzyme as a React component testing utility. My stronger experience is with the React testing ecosystem around Jest, and I understand the concepts behind component rendering and interaction testing."
